复习钱包基础 · 跳到引导式工作表 · 常见问题 · 要留下什么

你会用到的词

主密钥（master key）
该账户原来的签名密钥对。主密钥签名可以按账本规则禁用。
常规密钥（regular key）
一把单独配置、拥有宽泛签名权限的密钥；不是仅供查看的密码。
签名权重门槛（quorum）
一笔多重签名交易所需的最低合计签名者权重。
冻结（freeze）与追回（clawback）
冻结（freeze）限制代币的移动；在该能力已启用时，追回（clawback）可以收回发行方代币的余额。二者都不适用于原生 XRP。
黑洞化（blackholing）
试图移除账户可用的签名权限。把它当作永久失去控制权的决定，而不是安全评级。

做一张权限图

列出发行方、运营账户、已启用的主密钥签名、常规密钥（regular key）和签名者列表（signer list）。常规密钥可以授权大多数账户动作；它不只是一个只读 API 凭证。禁用主密钥签名，并不能证明其他签名途径都已消失。

有意地使用共享权限

签名者列表（signer list）设置各签名者的权重和签名权重门槛（quorum）。例如，三位独立签名者的权重各为 1，门槛为 2，就需要有效签名的权重合计达到 2。这只保护预期的那条签名途径：也要检查任何已启用的主密钥（master key）或常规密钥（regular key）。在转移权限之前，先在非生产网络上测试恢复。

区分这些控制

在有要求时，发行方授权（authorization）控制谁可以持有一种货币。单项冻结（individual freeze）限制通过信任线（trust line）的支出；深度冻结（deep freeze）再加上接收限制，并有与发行方直接往来的例外。全局冻结（global freeze）影响更广。这些代币控制不会冻结原生 XRP。追回（clawback）是另一项能力，应当单独披露；它不是冻结的另一个名字。

把不可逆的选择当作不可逆

No Freeze 永久放弃单项冻结（individual freeze）和深度冻结（deep freeze）的权限，以及清除全局冻结（global freeze）的能力；它不是一项“以后任何限制都不可能存在”的笼统承诺。黑洞化（blackholing）旨在移除可用的签名权限。这两个标签都不能证明分配公平、有流动性、有资产支撑或应用代码安全。请检查实际的账户设置和每一条签名途径，而不要依赖一枚徽章。

也要检查已委托的权限

在网络支持权限委托的地方，一个账户可以授权另一个账户执行指定的动作。受委托账户（delegate）不同于常规密钥（regular key），也不同于所有者账户上的签名者。在真正的权限审查中，要纳入已有的委托记录及其确切权限；一张只含三条密钥途径的图可能是不完整的。使用这项功能之前，请检查当前的修正案（amendment）支持，以及官方针对具体权限的警告。这门课不配置委托。

官方的权限委托指南和当前警告

画出谁可以代表俱乐部行动

虚构的 Issuer A 已禁用主密钥签名，指定了一把常规密钥（regular key），并有一份三人签名者列表（signer list），每人权重为 1，签名权重门槛（quorum）为 2。这是一个检查示例，不是建议的配置。

  1. 为第 1 课的每个账户画一个框。每个框下分别列出已启用的主密钥签名、常规密钥（regular key）和签名者列表（signer list）途径。如果公开记录回答不了某个问题，就写上未知；不要为了完成这张图去索取任何人的秘密。
  2. 对于签名者列表（signer list）这条途径，算出任意两位权重为 1 的签名者可以达到权重门槛 2，而一位则不能。现在圈出常规密钥（regular key）途径：它是一条替代的签名途径。只要另一条单密钥途径还在，即使签名者列表要求两人签名，也不能保证每笔交易都由两个人控制。
  3. 在纸上写下恢复情景：一位签名者不可用；两位不可用；一位签名者的安全已遭破坏；常规密钥（regular key）的保管人不在。说明哪些动作仍然可能，以及谁决定暂停运营。账本之外、要求两人批准的私人承诺，并不等于账本上的强制执行。
  4. 把代币控制与密钥分开列出：所需的授权、单项/深度/全局冻结（freeze）、No Freeze 和追回（clawback）能力。说明对持有人的影响，以及你检查过的证据。不要把某一条代币关系上的限制，理解成对 XRP 或每一种资产的限制。
  5. 标出不可逆或对顺序敏感的选择。No Freeze 不能撤销。信任线（trust line）追回（clawback）必须在发行方的所有者目录中出现条目之前，按其账户要求有意启用；它不是发行方以后可以随意补上的恢复按钮。实现之前，请核对当前确切的 AccountSet 规则。
  6. 写一份三列的用户披露：能力、现有证据和运营政策。例如：常规密钥（regular key）存在 / 观察到的账户字段 / 俱乐部说两名工作人员批准其使用。把最后一列标为政策，而不是协议保证。
决策过程示例

网站说，因为主密钥签名已禁用，所以没有人能改动这项资产。你的图上有一把常规密钥（regular key）。用对已启用途径和剩余能力的准确陈述替换这个说法。你没有足够的证据声称没有人知道一把密钥，也不能认证团队的保管做法。

可选：把工作表接到一条公开记录上

用只读账本浏览器（explorer）检查一个公开账户：查找账户标志（flags）、常规密钥（regular key）、签名者列表（signer list），以及该网络支持的任何委托记录。用所链接的官方定义来解释这些名称。只记录公开事实，并记下观察时间。浏览器里缺少一个面板，并不能证明某条权限途径不存在；请使用完整的账本数据，或让该项保持未解决。

官方 XRPL 账本浏览器目录 · 网络修正案（amendment）参考。仅仅阅读一条公开记录并不需要钱包。不要在这些练习里输入私人或个人资料。

常见问题以及要检查什么

两个签名仍然失败

检查签名者权重、签名权重门槛（quorum）、已授权的签名者身份，以及预期的账户/网络。不要把降低权重门槛或再启用一把密钥当作权宜之计。

冻结（freeze）被说成是在销毁代币

把余额限制与追回（clawback）或 NFT 销毁（burn）分开。询问正在使用的确切资产标准和控制。

一个团队想移除最后一条恢复途径

停下来，先做一份另行审阅的权限/恢复计划，以及隔离的演练。普通的应用回滚（rollback）无法恢复一条已经失去的签名途径。

继续之前要留下什么

保存权限图和白话的控制披露。请另一个人解释常规密钥（regular key）如何改变这个三取二的例子。如果他们说不清，就先改进说明，再进入签名流程那一课。

不签名，试着做

把这个例子做一遍

一个项目说“主密钥（master key）已禁用，因此没有人能更改任何东西。”它的账户仍有一把已启用的常规密钥（regular key）。这个结论有依据吗？

对照你的推理

否。常规密钥（regular key）仍然是一条权限宽泛的签名途径。检查它是否存在，以及签名者列表（signer list），然后记下哪些动作仍然可能。账户配置的公开证据，不能证明某人把秘密保管得多安全，也不能证明一把私钥是否真的无人知晓。

行动之前

这是一次检查练习，不是黑洞化（blackholing）的做法。跟随这一课时，不要禁用密钥、设置不可逆标志（flags），或移除签名者。

检查你的理解

禁用主密钥签名，也会禁用常规密钥（regular key）吗？

发行方能否用它的代币冻结（freeze）控制来冻结原生 XRP？

三取二的签名者旁边还有一把已启用的常规密钥（regular key）。是不是每一个动作都被强制经过两个人？

冻结（freeze）一枚发行代币，是否意味着发行方可以冻结持有人的原生 XRP？
