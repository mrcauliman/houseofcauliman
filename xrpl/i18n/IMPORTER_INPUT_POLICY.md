# Review CSV input and export policy

This policy describes the local importer hardening proposal. It does not certify a translation, authenticate a reviewer, approve a language, or authorize publication.

- Use comma-delimited UTF-8 CSV. A single UTF-8 BOM at the beginning of the file is accepted; it is not part of the header. Header names/order must exactly match the supplied packet. Duplicate, reordered, missing, extra or whitespace-altered headers are rejected.
- Every record must contain exactly the header's number of cells, including all empty decision cells. Empty files, blank records, missing/extra cells, invalid UTF-8, malformed quoted fields and oversized fields produce controlled errors before writes. Properly quoted commas and doubled quotes are preserved. Quoted newlines in unchanged context columns are supported; editable decision fields must be single-line because the Markdown packet stores each decision on a line.
- Returned input is parsed once, then those same in-memory rows are validated and applied. The importer does not reopen the returned CSV after validation. A zero-decision --apply performs no writes or downstream checks and creates no approval file.
- Correction text is preserved exactly, including ordinary leading/trailing spaces. Whitespace-only corrections are rejected. No apostrophe prefix, formula escaping, Unicode normalization, token replacement or automatic linguistic correction is written into the catalog. Approve/reviewer/date retain their existing surrounding-whitespace normalization for metadata.
- All incoming/exported cells are screened for spreadsheet formula-like leading =, +, - or @, including after whitespace, control/format prefixes and compatibility-width characters. Unicode compatibility normalization is used only for detection, never to rewrite data. C0/C1 controls other than quoted CR/LF context are rejected. Errors identify row/column and request explicitly reviewed plain-text wording. CSV quoting is not a defense against spreadsheet formula evaluation. This strict policy can reject a legitimate leading minus/bullet or formula example; resolve it deliberately with a reviewer rather than silently altering approved text. Do not enable spreadsheet formulas or external links when opening returned files.
- The exporter validates the entire output before opening an existing CSV. Apply preflights the merged CSV before any file write. Existing file rollback remains in place for Markdown/downstream-check failures. A failed restoration is not success; retain the diagnostic and stop.
- Preserved Latin tokens use explicit ASCII identifier boundaries and required occurrence counts; placeholders remain exact. Natural adjacent Japanese, Chinese or Devanagari text is allowed (for example XRPLは and NFTokenPageオブジェクト). XRPLfoo and $XRPfoo cannot satisfy standalone XRPL and $XRP requirements. Arabic/CJK/Devanagari and quoted Unicode text remain supported.
- Obvious AI/tool reviewer names are rejected after compatibility/format normalization. A name blacklist is not proof of identity, qualifications, native fluency or consent. A correction records status corrected with blank approve, not approval. Synthetic regression fixtures have no authority and never affect real reviewer packets.

Tests: python3 xrpl/i18n/tools/test_import_review_hardening.py, plus the existing four candidate checks. The release checker mechanically validates the declared state; --expect-held additionally enforces nine unapproved languages and zero decisions. Neither mode authenticates reviewers or authorizes publication; see DECLARED_RELEASE_CHECKS.md.
