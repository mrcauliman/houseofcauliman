# Declared-state checks and held-state regression

release.json remains a manual owner-controlled declaration. The checker is a mechanical consistency check, not proof of an authentic reviewer, native competence, owner acceptance or publication authorization. No new approval-evidence schema is introduced. Real release.json, catalogs and reviewer packets remain unchanged and all nine translations remain unapproved.

Run python3 xrpl/i18n/tools/check_release.py to check the declared state. Public output is derived from each language's declaration AND catalog completeness. It checks exact per-language canonical/hreflang URLs, notice, robots, baked public marker, selector options and proposed sitemap, using an independent HTML/XML oracle as well as the generator audit and full disk/render comparison. Unknown, missing or invalid states cannot pass. An incomplete catalog stays fail-closed even if declared approved; the separate catalog coverage check must still pass before any release decision.

Run python3 xrpl/i18n/tools/check_release.py --expect-held for this current candidate. It additionally requires all nine translations unapproved, blank reviewer decision fields and no decision-record files. It has been run on the actual isolated candidate; a mechanical mixed-state test does not satisfy this held-state regression.

Default mode allows structurally valid partial pending approve/correction metadata on a CSV and existing applied decision records. A recorded correction has status corrected and blank approve; it is never counted as native approval or used to change release.json. Existing record language/keys/status/name/date and packet metadata must agree; invalid or obvious tool-name metadata is rejected. The format does not authenticate a person or bind reviewed text cryptographically. External owner/reviewer gates remain mandatory, and a plausible name is not proof of qualifications. Pending CSV decisions are proposals, not acceptance.

Synthetic transition tests always begin from an explicit deep-copied all-unapproved fixture, independent of the real declaration or partial decisions. They prove single-language isolation, mixed declared states, withdrawal restoration, incomplete-catalog fail-closed behavior, and rejection of tampered metadata. Importer negative fixtures clear cloned decision cells so an existing real reviewer name cannot accidentally make a missing-reviewer test valid. All fixture data is TEST ONLY; original packet/release hashes are checked before and after.

Run test_release_declared_state.py and test_import_review_hardening.py for focused regressions, plus all four required candidate checks. None of these commands grants permission to edit release.json, publish a branch, merge, deploy, change protected root files or claim native approval. The proposed sitemap remains a proposal; never replace root sitemap.xml implicitly.
